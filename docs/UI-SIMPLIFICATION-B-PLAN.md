## 1. `src/app/(frontend)/(workspace)/products/page.tsx`（470 行 + 子组件 181 行）

### 1.1 实测到的「死参数」（最硬的一类，建议必删）

页面 `KEYS` 声明了 11 个筛选参数，但**侧栏只有「类别」与「品牌」两组 UI**：

| 参数                      | UI 是否存在                                  | 过滤逻辑位置             | 类别                     | 建议                                                         |
| ------------------------- | -------------------------------------------- | ------------------------ | ------------------------ | ------------------------------------------------------------ |
| `min` / `max`（价格区间） | **无**（全文件无 `name="min"`/输入框）       | `page.tsx:93-94`、`:117` | 非常用筛选（实为死参数） | **删**：KEYS 两项 + `toNumber` 若仅此处用则一并删 + 过滤分支 |
| `img`（有图/无图）        | **无**                                       | `:121-122`               | 非常用筛选（死参数）     | **删** 过滤分支 + KEYS 项                                    |
| `type`（设备类型）        | **无**（类别 navItem 的 href 只清空 `type`） | `:116`                   | 非常用筛选（死参数）     | **删** 过滤分支 + KEYS 项；类别筛选保留                      |

**为什么**：这些参数只能靠手改 URL 触发，普通用户不可达；留着会让过滤逻辑与 URL 契约看起来比实际能力多，也增加后续 Astryx 迁移的面。
**替代路径**：价格筛选若真需要 → 后续用 Astryx `RangeSlider` 补 UI（不是删能力）；当前无 UI 即无能力损失。
**步数影响**：0（用户现在就没有这两个筛选入口）。
