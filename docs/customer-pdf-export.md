# 客户交付 PDF 版式、页数与验收

客户交付页的「下载方案 PDF」与「下载报价单 PDF」使用同一固定 V 版本，**两份合计最多 10 页**。本轮改的是客户模版和分页，继续沿用白底 JPEG PDF 下载及浏览器打印路径。

## 客户能看到的变化

| 内容 | 新版式 |
| --- | --- |
| 方案页头 | 品牌、项目名、客户、地址、交付版本紧凑排列；联系方式减少重复，二维码有填才显示。 |
| 报价页头 | 编号与版本右对齐，项目名只出现一次；应收合计与费用摘要横排。 |
| 明细 | 细线分组、数字对齐；减少行内与分组间空隙，分组可以跨页，单条明细保持完整。 |
| 场景 | 触发与动作分栏；关联点位、确认状态及待定位说明保留。 |
| 楼层图 | 取消每层强制新页，标题与完整图片同组，可同页排列多图，不裁图。 |
| 收尾 | 报价说明、费用构成和联系方式各自完整，签字与日期横排。 |
| 页脚 | 下载每页显示「第 x / y 页 · 交付共 N 页」；交付页显示方案、报价单各自页数与合计。 |

品牌字段、全部真实报价行、单价、数量、合计、条款、未核验及配套未计入说明保留。报价正文、规格与核验说明、方案正文维持至少 9pt。没有用编造价格、删行、隐藏楼层或裁图来压页。

## 合计 10 页的规则

1. 每次点击任一下载按钮，都从当前固定版本准备**方案与报价两份完整内容**，等图片与字体就绪后一起测量。不沿用上次导出的页数，也不是两份各允许 10 页。
2. 优先正常间距；超过 10 页时，依次尝试紧凑、更紧凑间距。两份使用同一档，主要缩减留白、表格上下间距、缩略图和楼层图高度，正文不继续缩小。
3. 楼层不再强制独占一页。报价图高依次为 96 / 82 / 70mm；方案单层图最大高度为 128 / 104 / 88mm，多层为 110 / 96 / 82mm。图片完整等比显示，标题、单行报价和单张图不跨页裁断。
4. 一档能使合计≤10 页才下载；实际写入 PDF 的页面直接使用本次测量结果，页脚也使用同一页数。
5. 最紧凑版仍超限时，**停止下载并显示所需页数和 10 页上限**。所有内容仍在，不自动截到第 10 页；需要调整重复说明或重新规划实际交付范围。单条内容长到一页放不下也明确报错。

联合上限适用于「客户交付」的两个下载按钮。报价编辑页单独下载保留“先保存本页报价”的规则，只检查报价自身，不作为历史 V1 两份文件的联合验收入口。首次提案四套风格属于独立入口，不属于本次双份交付包。

「浏览器打印」保留可选文字和系统打印窗口，也会预检并选择间距。系统重复表头、打印缩放和页眉页脚可能改变最终页数，**原生打印的实际页数以系统预览为准**。下载文件的页码已画在页面中，不依赖阅读器支持。

5. 用微信按文件打开两份 PDF，滑到末页并放大点位图。再回网页点「浏览器打印」，确认窗口能打开，A4 预览完整；有打印机时实打小字和图纸各一页确认可读性。

```sh
node scripts/check-customer-pdf.mjs
```

离线脚本使用真实两套模版、构建后的打印样式及产品下载器，数据明确标为虚构。准备 1 层 / 4 层各 26 行，以及 400 行超限场景；全程 file://，拦截网络请求，不访问客户数据库。完整运行将检查：两份实际 PDF 合计≤10、预估与实际页数一致、每页页码、全行与全图保留、逐行不跨页、金额/核验说明、300 dpi、失败清理、超限无下载且不删行。

结果写入忽略目录 `output/pdf/customer-pdf-check/`。`--prepare-only` 只验证模版渲染和下载器打包，**不产生实测页数，也不算 PDF 验收通过**。脚本成功后仍需目视检查逐页图片。

本轮：29 个测试文件、259 项相关测试及类型检查通过；改动代码检查 0 错误，方案入口保留 2 条既有提示；差异格式检查通过，三组离线页面准备成功。实际浏览器执行受 `SIGABRT / EPERM` 限制，报告为 `prepared=true / browserExecuted=false / passed=false`，没有新 PDF 或截图。真实本机页面自动访问也被工具权限拒绝；未改用其他方式绕过。真实 V1、新文件页数、Preview、微信及纸张效果均待 lynn 按上述步骤确认。客户数据库、固定 V1、价格和无关大图没有改写；改动仅在本机工作区，未部署、未推送。
