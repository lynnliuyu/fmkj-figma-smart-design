### 重复点：名片 / 模板中心 / 全部工具（确认）

三项都指向 `/capabilities/*`，而 `/capabilities`（能力中心总览）与 `/capabilities/[id]`（详情）也在，只是没进侧栏。
也就是说：**能力中心被拆成 3 个侧栏入口 + 2 个无入口页面**。

| 现状                                | 问题                                                 |
| ----------------------------------- | ---------------------------------------------------- |
| 侧栏 3 项（名片/模板中心/全部工具） | 同一批能力的三个切片，用户要记「哪个能力在哪个入口」 |
| `/capabilities` 总览页无入口        | 有页面但进不去（只能手输 URL），实际成了死页面       |
| `/capabilities/[id]` 详情页         | 只能从总览页进，而总览页无入口 → 整条链实际不可达    |

**简化建议（待拍板）**：侧栏保留 **1 个「能力中心」**，进去后分 3 段（AI / 模板 / 工具），
名片、模板中心、全部工具都从那里进。侧栏从 7 项降到 5 项。

## 4. 三个重页的「可去掉项」清单

### 4.1 `/projects`（405 行 page + 子组件共 830 行）

现状：4 个统计卡 + 状态筛选 + 搜索 + 表格。

| 可去掉 / 折叠                                        | 理由                                                             | 影响                                                 |
| ---------------------------------------------------- | ---------------------------------------------------------------- | ---------------------------------------------------- |
| **4 个统计卡**（进行中/累计点位/报价总额/报价·签约） | 占首屏约 1/3；数字要从全库聚合查询（成本高），且表格里能逐条看到 | 首屏直接进列表；如需保留，收进「概览」抽屉或列表页脚 |
| 搜索按钮（`搜索`）                                   | 已输入关键词还要再点一次                                         | 改回车/即时筛选（保留回车，去掉按钮）                |
| 「示例」Badge 与演示项目提示                         | 仅内部识别用                                                     | 可改为列表底部一行说明                               |

### 4.2 `/products`（470 行 page + 子组件共 651 行）

现状：标题+搜索 + 左侧筛选（类别/品牌/平台/价格）+ 产品网格 + 分页。

| 可去掉 / 折叠                      | 理由                                         | 影响                           |
| ---------------------------------- | -------------------------------------------- | ------------------------------ |
| **左侧筛选里的「价格区间」**       | 销售查产品基本按类别/品牌/型号，价格筛选少用 | 少一个输入区；搜索框已支持型号 |
| 「平台」筛选（如果与品牌高度重合） | 平台信息在产品卡上已有                       | 需先核对数据分布，避免误删     |
| 分页「上一页/下一页」双按钮        | 可合并成「加载更多」                         | 减少一次滚动回顶               |

### 4.3 `/print/quotes/[id]`（975 行，7 个 table）

现状：**一个文件里塞了 4 种版式**（`standard` / `system` / `budget` / `area`），每种都有自己的表头、汇总、页脚。

| 可去掉 / 折叠                    | 理由                                                                        | 影响                                              |
| -------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------- |
| **`system`（系统汇总版式）**     | 与 `standard` 的信息重叠（系统汇总 = 按类别分组的明细），且只在打印时多一页 | 需用户确认是否真在用；不用则删一整段（约 150 行） |
| **`budget`（方案预算概览版式）** | 与「方案演示」插件输出的预算页重复                                          | 确认后删（约 120 行）                             |
| 每版式各自的页脚/签名区重复实现  | 4 份近似代码                                                                | 抽成共用组件（属重构，不是简化）                  |

> 打印页**不建议动版式本身**（版式即交付物），但「4 版式是否都要」值得用户拍板。
