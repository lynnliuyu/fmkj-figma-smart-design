# 0010 同一业务系统提供线上与本地部署，官方产品库独立订阅

Status: Accepted
Date: 2026-10-21

## Context

用户决定提供两个交付版本：完善后上线的线上托管版，以及在黑豹 X2 小服务器上预装、配置并发货的本地部署版。本地设备通过 Docker 更新软件；两种版本都允许使用官方收费产品库、自己维护产品库或混合使用。此前只讨论产品库订阅，未完整表达这两种交付方式。

## Decision

- 两种部署共用一套业务核心和版本体系，以部署配置及存储、升级等适配层区分。开源业务代码继续采用 MIT；官方产品主库、订阅凭据和商业服务独立管理，不随源码或公共镜像分发。本决策不改变第三方代码、素材的原有许可。
- 业务数据库保存用户、客户、项目、点位、报价和固定交付；产品资料库提供型号、参数、素材与来源。线上业务数据由托管服务保存，本地设备默认保存自己的业务数据，不因接入官方产品库而上传客户项目。
- 官方产品库以授权服务同步到部署实例；自建库由用户维护，混合使用保留用户价格、备注和修改。官方产品身份与部署内产品 ID 分开，更新不重新生成已有产品 ID，也不回写历史报价与交付版本。
- 软件升级、产品库同步、业务数据备份是三个独立流程。本地版核心工作流以离线可用为目标，联网用于管理员选择的软件更新及授权产品库同步；浏览器缓存不替代服务器数据和备份。
- 托管服务权益、官方产品库订阅、设备售后/维护分别表达。官方产品库到期只影响获取新增资料和后续更新，不锁本地业务写入、不删除已同步资料；既有账号体系的过期锁写规则不能直接用于产品库订阅。线上托管到期、设备维护期限及具体价格仍待单独确定。
- Docker 更新由独立部署管理端执行；业务应用不直接拥有 Docker socket 或任意宿主机命令执行能力。更新针对明确版本，包含备份、数据库兼容检查和健康验收；数据库结构变化后的恢复不能仅靠切回旧镜像。

## Consequences

首版保留单体业务应用，不先拆分点位、报价和交付服务。需要补齐本地持久化文件存储、官方产品来源映射与同步、发布镜像及部署管理能力；线上开放前必须验收企业数据隔离。设备具体硬件、价格与付费范围没有因本 ADR 自动确定。

架构方案见 [双部署与产品库架构](../deployment-and-catalog-architecture.md)，实施顺序见 [Plan 028](../../plans/028-hosted-local-and-catalog-foundation.md)。Accepted 代表方向确定，不代表这些功能已经实现或线上版可以开放。
