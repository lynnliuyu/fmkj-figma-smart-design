### ★★ 推导脚本踩的 8 个陷阱（写规则类脚本必看）
1. **产品族命名里的关键词 ≠ 该产品的规格**：Somfy Sonesse 描述写「产品族（30/40/50/Ultra/**PoE**）」，把 PoE 推给了窗帘电机。**PoE 是网络设备供电标准，与窗帘电机无关**
2. **系列聚合条目不能取单值**：领普「E2 Lite 系列墙壁开关」1 条记录涵盖 6 个变体（白/灰 × 单/双/三键），描述是「原名：A 单键/A 双键/A 三键…」。正则会命中第一个「单键」→ 推出错误的 button_count=1。**必须在「描述含 ≥3 种键数变体」时拒绝推导**
3. **正则匹配到邻近数字**：`额定功率：39W` 被推成承重 80kg。功率和承重单位不同，必须要求原文出现「承重/负载 X kg」
4. **占位文字当数据**：「屏幕尺寸待核」被当成有尺寸线索。要显式排除「待核/待确认」类词
5. **枚举值大小写**：推出 `WI-FI6`，应规范为 `Wi-Fi 6`
6. **`type=number` 的字段不能从分辨率推**：`1920` 之类不是屏寸
7. **USB 字样 ≠ USB 供电**：要匹配「USB 供电 / Type-C 供电」而不是裸 `USB`
8. **中控屏 relay_count 一律 0** 只对旋钮/纯面板成立；描述里带负载参数的要逐条核

**结论：写这类推导脚本必须「先跑一遍 → 打印全部推导结果 → 逐条人工抽检可疑项 → 再写入」，不能直接写库。** 本轮就是先跑出 141 条、发现 4 处错误、修完再写。

- 价格依据 61 条

### ★★★ 发现并纠正的严重问题：103 条假依据
旧依据统一写着：
> 「由旧产品库表格恢复（来源：产品库表格.xlsx / 产品库导出.xlsx）。厂家型号、结构化规格与设备类型均未核实，保持待核；**未按名称或分类猜测继电器路数、屏幕尺寸等参数**。」

**但上一轮我恰恰按名称推导了这些参数** —— 依据与事实自相矛盾。假依据比没依据更危险：客户看报价单时会误以为参数有官方来源。

已全部改写为逐字段列出推导理由：
```
参数由产品名称与官方描述推导，逐字段依据如下：button_count=3（名称含「三键」）；
relay_count=3（控电型开关，继电器路数 = 按键数 3）；wiring="neutral"（名称/型号含「零火」或 neutral）。
推导值未经型号页逐项复核，保持待核。
```

### 依据格式规范
**参数依据**：优先保留旧依据中含官网/说明书/官方/实测的部分；**含「未按名称猜测」的必须整段丢弃**（否则自相矛盾）。有推导依据时逐字段列 `字段=值（理由）`。

**价格依据**：优先取 description 里已有的「定价：」片段（含搜索快照来源与国补备案型号）→ 否则用采集底稿的 source/pageUrl → 都没有则明写「来源未记录，需重新核价」。结尾统一附「售价￥X，成本￥Y；未按当前渠道复核，保持待核。」成本为 0 写「成本未知（0 表示缺失，不代表零成本）」。

### ★ 为什么没有提升为 verified
指南明确：「**不能为了让报价显示『已核验』而提升缺证据的产品状态**」。
本轮依据是按名称与描述推导的，未经型号页逐项复核 → `selection_status` 保持 pending。
**全库 789 条 selection_status / pricing_status 现在全是 pending，verified 0 条。**

### ★ API 写入依据时必须带的完整字段
除基础字段白名单外，还要同时携带（否则会被清空）：

```
parentProductId / manufacturerModel / selectionStatus / pricingStatus / mappingRevision
```

### 指南里的其他关键规则（后续必须遵守）
1. **系列不是具体 SKU**：一条资料写着 1/2/3/4 键价格，属于系列线索，不能变成一个「四键开关」。只为证实存在的供货配置建子 SKU，`parentProductId` 指向父系列。父子设备类型一致。
2. **只有证实「没有继电器输出」时 `relay_count` 才能填 0** —— 不能因为「触控屏大概不控电」就填 0。
3. **「米家」不是通信协议**；共享的 BLE Mesh 标签不证明每款设备都有该协议。
4. **屏幕型号中的数字不直接写成英寸**。
5. **成本未知时保留待核，不能按售价乘固定折扣推算**。
6. 新产品无价格时只能作为 `pricingStatus=pending` 的未知占位，并在证据中写「售价/成本未知」—— **不表示免费或零成本**。
7. 类型字典缺项（如 NVR）要「记录缺项 + 改代码和规则」，**不能只插字典表或借用不相干类型**（本轮 nvr 三处同步符合这条）。
8. `specs` 不接受任意字段；尺寸、材质、颜色、PoE 端口细分、详细电气负载放采集底稿和描述，**不擅自塞进 specs**。
9. 角色不明确的继续 `legacy`（如 C2/Cielo、H3 筒/射灯冲突），不能靠名称强行解决。
