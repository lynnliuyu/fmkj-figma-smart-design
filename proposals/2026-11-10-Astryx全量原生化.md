## 0. 变更摘要

**删掉 `src/components/ui/*` 的适配层，全站 713 处调用点改为直接调用 Astryx 官方组件。**

现状是「保留旧 API、内部转译到官方组件」的兼容层。本提案改为官方文档推荐的做法：
**直接使用官方组件**（官方原文：_"Do not wrap old shadcn components in design system styles.
Replace the primitive with the component that owns the behavior, accessibility, state classes,
and token usage."_）

依据文档：`astryx.atmeta.com/docs/migration`、`/docs/getting-started`。

### 1.2 兼容层已经造成的 4 次真实故障

| #   | 故障                               | 根因                                                                      |
| --- | ---------------------------------- | ------------------------------------------------------------------------- |
| 1   | Popover 完全不渲染                 | 官方 Button 不转发 ref                                                    |
| 2   | **生产环境侧边栏 10 个菜单全消失** | 适配层靠**函数名**识别子组件，生产压缩把名字压没了                        |
| 3   | 9 处下拉菜单点不开                 | 适配层挑字段传 props，`ref` / `aria-haspopup` 被丢弃                      |
| 4   | **37 个 `outline` 按钮看似隐形**   | 适配层又写了一行 `data-variant={旧名}`，**把官方 CSS 的属性选择器顶掉了** |

第 4 条的实测证据（同一页面两个按钮对照）：

```
纯官方 <button class="astryx-button" data-variant="secondary">
    → 边框 1px 灰、背景透明          ✅ 官方样式生效
适配层产出的按钮（本仓 outline）
    → data-variant="outline"（被覆盖）
    → 边框 0px、背景 6% 黑           ❌ 官方的 secondary 样式选不中它
```

**关键发现**：官方 `secondary` 的真实样式就是「透明底 + 1.5px 描边」——
**即本仓 `outline` 应有的样子**。所以映射方向是对的，坏的是「两套命名同时写在一个元素上」。

### 1.3 兼容层还在制造的其他代价

- 每次换主题要人工「读 token 对齐」保留的 8 个组件
- 官方组件的状态机（hover / aria-expanded / disabled）没有真正接管
- 官方 174 个组件里有大量本仓没有的能力（ButtonGroup / Banner / AlertDialog…）用不上

## 2. 修改前 / 修改后

### 修改前

```tsx
// src/components/ui/button.tsx —— 适配层
export function Button({ variant = 'default', size = 'default', asChild, ...props }) {
  const v = variant as Variant
  if (asChild) return <Slot.Root data-slot="button" data-variant={v} {...props} />
  const { icon, rest } = splitLeadingIcon(props.children)
  return (
    <AstryxButton
      variant={ASTRYX_VARIANT[v]} // outline → secondary
      label={label}
      data-variant={v} // ← 这一行把官方的属性选择器顶掉
      {...(rest as object)}
    />
  )
}

// 调用点：331 处
;<Button variant="outline" size="sm">
  <Sparkles />
  生成点位
</Button>
```

### 修改后

```tsx
// 调用点直接调官方组件，import 自各自入口
import { Button } from '@astryxdesign/core/Button'
import { IconButton } from '@astryxdesign/core/IconButton'

;<Button variant="secondary" size="sm" icon={<Sparkles />} label="生成点位" />

{
  /* 图标按钮用 IconButton —— 官方专门为工具栏图标按钮提供的组件 */
}
;<IconButton variant="ghost" size="md" label="网格" icon={<Grid />} />
```

**映射规则**（本仓旧名 → 官方名）：

| 旧                      | 官方                 | 说明                                     |
| ----------------------- | -------------------- | ---------------------------------------- |
| `variant="default"`     | `primary`            |                                          |
| `variant="outline"`     | `secondary`          | 官方 secondary = 透明底 + 描边，语义吻合 |
| `variant="secondary"`   | `secondary`          |                                          |
| `variant="ghost"`       | `ghost`              |                                          |
| `variant="destructive"` | `destructive`        |                                          |
| `variant="link"`        | `ghost` + 链接语义   | 12 处，逐个判断                          |
| `size="default"`        | `md`                 |                                          |
| `size="sm"` / `"xs"`    | `sm`                 |                                          |
| `size="lg"`             | `lg`                 |                                          |
| `size="icon*"`          | 改用 `IconButton`    | 图标按钮是独立组件                       |
| `disabled`              | `isDisabled`         |                                          |
| `asChild` + `<Link>`    | `href` + `as={Link}` | 官方内建链接支持                         |
| children 里的图标       | `icon` 插槽          |                                          |
| children 里的文字       | `label`              |                                          |

## 3. 影响范围

- **只动 UI 层**：`src/components/ui/*`（适配层删除）+ 713 处调用点
- **不动**：数据模型、Payload 配置、API 路由、业务逻辑、权限、导航结构
- **不动的理由**：本次是「同一批组件的调用方式替换」，页面信息架构与数据流保持不变

**因此不属于 §0.1 列的架构变更范畴**（模块边界 / 数据模型 / 权限 / 信息架构均不变），
严格说不需要提案。但改动量大（713 处 / 82 文件），**按 §0.3「拿不准时按架构变更处理」留档**。

## 4. 数据迁移 / 兼容

**无数据迁移。** 纯前端组件调用方式变更。

**分阶段兼容**：迁移期间新旧并存 ——
官方组件（`@astryxdesign/core/Button`）与本仓适配层（`@/components/ui/button`）
可以同时存在，按文件逐个切换，每个 PR 都能独立上线。
