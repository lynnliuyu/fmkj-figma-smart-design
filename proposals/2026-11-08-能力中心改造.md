## 0. 变更摘要（§0.1 规定格式）

```
修改前：
  用户入口叫「插件市场」，位于 /plugins（另有 /plugins/[id] 详情、/plugins/toggle 开关接口、
  /plugins/tools 独立功能入口页）。侧边栏只有「工作台」+「插件」两个分组，其中「插件」分组
  下含：插件市场、插件功能、AI 生图、户型图风格化。
  用户可以自行「安装 / 启停」插件：启停状态存在 users.companyProfile.disabledPlugins（json 数组，
  另有 legacy global 字段 CompanySettings.disabledPlugins），写入入口为 POST /plugins/toggle
  （以及一处已无 UI 的孤儿接口 settings/company/route.ts）。
  组件状态由 src/plugins/state.ts 合成：status==='ready' && 未 disabled && tier 足够；
  全仓约 28 处读取（页面级判定，无中间件级开关），不满足即 404 / 前端隐藏。
  插件清单无「分类」字段，仅按 stage（design/quote/build/after/global）推出展示分组。
  模板不成体系：方案模板在公开页 /templates；文档风格在「设置 → 文档模板」；
  「点位图显示方案」在代码中不存在。

修改后（目标形态，见 §4.6 / §7）：
  用户入口改称「能力中心」，分三类：
    能力中心
    ├─ AI 能力（户型图风格化 / 智能布点 / AI 生图 / AI 识图）
    ├─ 模板（方案模板 / 点位图显示方案 / 文档风格）
    └─ 工具（DWG·DXF 转户型图 / 其他独立工具）
  侧边栏分组改为：工作台（项目 / 产品库 / AI）、能力中心（AI 能力 / 模板 / 工具）、
  账号（使用报告 / 积分账单 / 账号设置 / [超管] AI 渠道配置）。
  普通用户不安装、不启停插件，点卡片直接进对应页面按积分使用。
  模板中心 /plugins/templates，三个 Tab：方案模板 / 点位图显示 / 文档风格。
  UI 不再出现「插件」字样；内部仍可用插件注册表实现。
  超级管理员是否保留「全局隐藏 / 维护开关」见未决问题 B。

影响范围：
  导航/IA：src/components/app-sidebar.tsx（分组重排）、src/components/site-header.tsx（标题映射）、
    路由入口（/plugins 是否原地改名见未决问题 E）。
  插件层：src/plugins/types.ts（新增分类字段）、index.ts（12 项分类归属）、state.ts（启停语义）、
    ai-catalog.ts / plugin-ai-specs.ts / plugin-tools.ts。
  启停逻辑：getPluginFlags 的 28 处读取点（工作区页 / 打印页 / 小程序 API / 服务层）需改为
    「按能力是否存在」而非「用户是否启用」。
  模板中心：新增 /plugins/templates 路由与三个 Tab；方案模板选择器现有分散实现需收敛；
    文档风格入口从「设置」上移到模板中心；「点位图显示方案」为**新建功能**（见未决问题 G）。
  前端文案：全仓约 77 个文件含「插件」字样需清理（含小程序 pages/mine、docs/USER_MANUAL.md、
    knowledge/*.json、promotion-kit）。
  小程序：mp/v1/meta 直接吐 plugins，pages/mine 有「已启用插件」弹窗，需同步。
  数据：users.companyProfile.disabledPlugins（迁移见未决问题 D）。

数据迁移 / 兼容：
  用户侧无「业务数据」需要换算：启停只是一个偏好数组，清空即可（团队/公司能力未上线）。
  若保留超管全局开关，则 disabledPlugins 语义从「用户偏好」改为「平台级维护位」，
  需要一次数据迁移把用户级值清空、只保留平台级值。
  类目/分类是**新增类型字段**（现有清单只有 stage），属于类型层扩展，无数据回填。
  「点位图显示方案」若纳入本提案，需要新增 collection / 项目级字段，属**新增数据模型**，
  建议拆到独立提案（未决问题 G）。
  无付费客户、无等级折算（与「取消会员分级」提案无数据冲突，但代码面重叠，见未决问题 C）。

回滚方式：
  纯前端/文案/导航改动可 revert 提交即恢复。
  若已改 disabledPlugins 语义并跑过迁移，回滚需一并恢复该字段的读写逻辑；建议迁移前
  备份 users.companyProfile.disabledPlugins 快照。
  不改数据库表结构（除非采纳 G 的新模型），因此回滚成本低于「取消会员分级」提案。

需要谁批准：
  项目 owner（noone）。属 §0.1「模块边界、导航层级、插件 / AI 模块归属」变更，必须书面批准。
  批准后按 §0.1 更新 PROJECT-ARCHITECTURE.md 并改代码。
```

## 3. 风险与未决问题

### 3.1 风险
1. **读取点众多（28 处）**：任何漏改会留下「能力打不开」的死角，必须靠 `pnpm build` + 全量 grep 兜底。
2. **无测试框架 / 无 lint**：改动面大却缺少自动化护栏，回归风险高于「取消会员分级」提案。
3. **文案清理范围大（77 文件）**：容易与其它在途分支冲突。
4. **「点位图显示方案」是新建功能**：若强行塞进本提案，会把一个纯 IA/命名改造撑成含新数据模型的大改，建议拆开。
